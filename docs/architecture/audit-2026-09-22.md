## Verified findings

### Dependency graph (353 source files, 1,059 internal edges under `lib/`, `app/`, `components/`)
- No `@/` path alias exists; all imports are relative with `.js` suffixes. Several docs said otherwise.
- The engine barrel loads Prisma: `lib/engine.ts` → `engine/index.ts` → `engine/public.ts` → `lib/engine-state.ts` → `adapters/runtime/engine-state.prisma.ts` → `lib/prisma.ts`, and `lib/engine/legacy.ts` → `lib/legacy-engine.ts` → `adapters/runtime/legacy-engine.prisma.ts`. `check:engine-prisma` did not catch this because its import regexes ran after string literals were blanked (dead patterns; only `prisma.` usage was checked).
- One value cycle: `lib/engine.ts` → `engine/public.ts` → `lib/scan-helpers.ts` → `lib/engine.ts`.
- Direction inversions: `lib/auth.ts` imports an `app/api` route; `lib/autopilot/runSimulation.ts` type-imports `components/autopilot/*`.
- `lib/prisma.ts` has 66 importers; 17 API routes use it directly, 6 only through runtime adapters.
- Routes call `safeSolveDecisionForWorld` (deep import of `lib/engine/run.ts`) plus the legacy engine; nobody calls `safeSolveDecisionForUser` except the offline evaluator.
- `lib/adapters/index.ts` and `lib/schemas/index.ts` have zero importers. Zero-importer candidates: `lib/adapters/runtime/{ConsoleLogger,FetchClient,NodeCrypto,NodeFilesystem,PrismaDatabase,SystemClock}.ts`, `lib/autopilot/recent-decisions.ts`, `lib/engine/autopilot.ts`, `lib/history.ts`, `lib/ingest/bank-transactions.ts`, `lib/simulation.ts`, `lib/schemas/autopilot.ts`, `lib/ui.ts`, `lib/util/{boolean,brands}.ts`, `lib/verification/{bank,receipts,vine}.ts`, `lib/authority/replayAuthority.ts` (*deletion not verified safe*; some are named in allowlists).
- Largest modules: `lib/autopilot/service.ts` 838 lines, `lib/engine/objective.ts` 537, `lib/accounting/ledger.ts` 514, `app/api/simulate/route.ts` 460. Highest fan-out: `app/api/scan/route.ts` and `app/api/simulate/route.ts` (22 imports each).

### Documentation vs code
Corrected in this change: non-existent `app/(marketing)` and `dist-scripts/`; `@/lib/prisma`; `withUser` described as universal (9 of 35 routes use it); `getServerSession`; CI steps; `check` described as "guardrails + lint + typecheck" (it also runs node and next tests); `.js` specifiers described as forbidden; duplicate guardrail numbers 44 and 57; doctrine §1.2 claiming `fromLegacy` may use time and DB (both guardrails ban it); doctrine §2.1 "never" (six guardrails are allowlisted); `/dev` "gated by middleware" (it is `proxy.ts`, and five dev pages are outside its matcher); legacy test paths cited in three docs. Deleted five docs that declared themselves deprecated and `DOC_REWRITE_TASK.md`.
Not changed here: `/signin` had no `page.tsx` while NextAuth points at it (deleted by accident in `7668dd1`; restored in a follow-up PR, which also redirects `/` to `/app`); `docs/api.md` omits seven routes (now listed there as undocumented).

### Enforcement classification
Enforced: engine no-Date, engine no-Prisma (now including value imports), guardrail/runtime separation (with allowlist), `EngineInput` boundary, engine version gates, script runner contract, registry/doc parity, DB truth via named scripts. Documented only: `withUser` on stateful routes, Prisma only via adapters, bucket math via `buckets-runtime`, the engine-freeze content rules (four `feat(engine)` commits since the freeze, no exception entries), evaluator read-only, `upsertBankTransactions`-only ingest, locale-free SSR. Local only: `check:change-isolation` (no-op in CI).

### Tests
- 110 legacy files (`tests/*.test.*`, `tests/guardrails`, `tests/authority`, `tests/migrations`, `tests/type`, plus `tests/helpers`, `tests/__mocks__`, `tests/accounting`, `tests/engine`) duplicate `tests/node`/`tests/next`. Two pairs diverged in logic (`engine-solver`, `api-sessions.user-context`). `check:guardrails-core` requires 25 legacy paths to exist; `check:engine-optimality` runs the legacy `tests/engine/optimality` copy; `tests/node/engine/optimality` and `tests/accounting` run nowhere.
- CI runs node and next tests three times.
- No framework; mixed ESM/CommonJS import styles across test files.

### Repository hygiene
- `cherry-diff.patch` (47 KB) is a committed working-tree snapshot verified by `verify:cherry-diff-artifact`; it goes stale by construction. `docs/config-snapshot.md` (405 KB) is generated but required by two guardrails. `AUDIT.md` is a historical one-off referenced only by the full-checkout audit script.
- `.evidence/latest.json` was not ignored; `scripts/audit/full-checkout-audit.mts` was ignored but tracked and required by a guardrail; `*.pem` listed twice. Fixed.
- `data/bank/moustafa-adv-safebalance-2061.csv`: commit `d6b8651` states it is a synthetic replacement, but earlier history (`ddc864b` and before) still contains real exports. **Separate remediation required** (history rewrite is a deliberate, coordinated action; not done here).
- `data/mcc/sanitized-mcc.txt` is byte-identical to the `.tsv` and unused; `Merchant-Category-Codes.pdf` and `unsanitized-full.txt` are unused (left in place; not required for reproducibility, not harmful).
- No tracked secrets found. `scripts/dev-login.sh` contains a hard-coded dev password (dev-only). `lib/wallet/cherryPass.ts` derives the Wallet `authenticationToken` from the user id with a constant fallback, which is guessable (*security review recommended before enabling the pass*).
- `scripts/side-effects.allowlist.json`: all ten `legacy-combo` entries carry `expiresBy: 2026-06-01`. `check:side-effects:diff` compares against the HEAD commit date, so **any commit dated after 2026-06-01 fails `npm run check`** until the entries are remediated or the policy is revisited. This was pre-existing. **Resolved** by fixing the detector: the ten modules only convert supplied timestamps, so `check:side-effects` now counts only real clock reads and the entries became `persistence-only` (PR #32).
